# Pixel Action Roguelike — базовый документ проекта

Один файл, который сводит всё: что за игра, как её запустить, как устроен код и почему он устроен
именно так, чем закончились тринадцать забегов плейтеста и что показало ревью. Остальные документы
([PLAYTEST.md](PLAYTEST.md), [docs/superpowers/](docs/superpowers/)) остаются источниками; здесь —
их суть и разбор кода рядом с ней.

---

## 1. Что это за игра

Пиксельный экшн-рогалик в духе Vampire Survivors, но **без оружия у игрока**: весь урон наносят
**фигуры** (турели, духи, моты, дрон-мины), а игрок занят другим — он **добывает Ток** и **управляет
вниманием врагов**. Петля:

```
двигаешься → собираешь батареи и осколки → кормишь Ток → фигуры работают → убиваешь →
берёшь карты → ветка становится профессией → забег ускоряется → умираешь → медаль → новый забег
```

Ключевые механики (все они меняли игру по ходу плейтеста, см. §7):

| Механика | Суть | Где живёт |
|---|---|---|
| **Ток** | Единственный ресурс. Плата за ПОСТАНОВКУ фигуры + постоянный ЗАЛОГ живой фигуры | [systems/charge.ts](src/systems/charge.ts) |
| **Батареи** | Появляются вдали от игрока: чтобы кормить фигуры, надо двигаться | [systems/pickups.ts](src/systems/pickups.ts), [systems/supply.ts](src/systems/supply.ts) |
| **Осколки** | Падают там, где убили, живут секунды: урон тоже кормит, но рискованно | там же |
| **Напряжение** | Полный Ток ускоряет фигуры на четверть: энергия влияет на бой, а не на бюджет | [systems/charge.ts](src/systems/charge.ts) |
| **Пул ошибок** | Три удара вместо мгновенной смерти; контакт всегда в пул, броня гасит дальний урон | [systems/armor.ts](src/systems/armor.ts) |
| **Виды врагов** | Погоняла, танк, стрелок, делитель — различаются ТРЕБОВАНИЕМ к игроку, а не HP | [config/enemyKinds.ts](src/config/enemyKinds.ts) |
| **Элиты** | Вид плюс одно свойство (щит / быстрый / взрывной), видно обводкой | [systems/spawnDirector.ts](src/systems/spawnDirector.ts) |
| **Ветки и профессия** | 3 ветки карт; набрала 2 карты — стала профессией; открываются крос-карты | [core/progression.ts](src/core/progression.ts) |
| **Мета** | 5 медалей за завершённые забеги дают бонусы на СТАРТ следующего | [core/meta.ts](src/core/meta.ts) |
| **Режимы** | Хардкор (по умолчанию) и обычный — разные таблицы результатов | [config/tuning.ts](src/config/tuning.ts) |

## 2. Как запустить

### Игрок: один двойной клик

Распаковать папку `dist/` и дважды кликнуть **`Играть.bat`** (Windows) — или просто открыть
`index.html` любым браузером. Интернет, установка и сервер не нужны: **вся игра — один HTML-файл**
(~1.4 МБ: вшитый движок Phaser, код и спрайты как data: URI). Рядом лежит [ЗАПУСК.txt](public/ЗАПУСК.txt)
с управлением. На телефоне — открыть тот же `index.html` (или залить на любой статический хостинг).

Почему именно так, а не «открыть файлы с диска»: браузер **не отдаёт локальные картинки в
WebGL-текстуры** (`texImage2D` бросает `SecurityError` — проверено на Chrome), а модульный скрипт из
`file://` не грузится вовсе (CORS для origin `null`). Поэтому спрайты встроены в сборку как
data: URI, а JS вшит в HTML — это делает [tools/build/packSingleFile.mjs](tools/build/packSingleFile.mjs)
последним шагом сборки и там же проверяет, что внешних ссылок не осталось.

### Разработчик

```
npm install
npm run dev      # живая разработка на http://127.0.0.1:5173
npm test         # 111 тестов, node --test, без браузера
npm run typecheck
npm run build    # tsc + vite build + упаковка в один dist/index.html
node tools/qa/file-launch-smoke.mjs   # смоук: dist запускается из file://, мир живой, ошибок нет
```

Смоук-тест упаковки гоняет headless Chrome по-настоящему: открывает `dist/index.html` из файла,
жмёт «1» (выбор таланта), проверяет, что мир движется, пиксели не пустые, а консоль чистая. Он же
однажды нашёл настоящий баг клавиатуры (§9).

## 3. Стек и структура

**Стек:** Phaser 4 (движок), TypeScript (strict, включая `noUnusedLocals`), Vite (сборка),
`node --test` (тесты, без единой тестовой зависимости), WebAudio-синтез (звук без файлов).
Зависимости ровно три в `package.json`: phaser, vite, typescript.

```
src/
  config/      числа и данные: tuning (все «ощущенческие» числа), art + textures (спрайты),
               enemyKinds (таблица видов врагов)
  core/        чистая логика без браузера: progression, charge-связки, meta, intro, runStats,
               runHistory, runRecord (версии правил), rng, math, viewport, store
  sim/         FixedStep — фиксированный шаг симуляции 120 Гц
  systems/     игровые системы: charge, supply, pickups, pressure, spawnDirector, targeting,
               armor, projectiles, input, sfx
  entities/    enemy (машина состояний врага), ally (четыре роли фигур)
  scenes/      GameScene — единственная сцена: связка всего, HUD, экран смерти
  ui/          cards (выбор таланта), juice (эффекты), rotateHint (заглушка поворота)
tools/
  bot/         стенд замеров: policy (бот) + harness (прогонщик серии по сидам)
  qa/          смоук-тест упакованной сборки из file://
  build/       packSingleFile — упаковка dist в один HTML
  ts-resolve/  хук-резолвер, чтобы тесты импортировали .ts без расширений
docs/superpowers/  спеки и планы (см. §7); PLAYTEST.md — журнал забегов
```

## 4. Архитектура: два правила

**Правило 1: всё, что можно проверить без браузера — проверяется без браузера.** Чистые модули
(никакого Phaser, никаких часов и случайности внутри) живут в `core/`, `systems/`, `config/`;
сцена подаёт им данные и рисует результат. Поэтому 111 тестов гоняются за две секунды, а спорный
баланс проверяется замером до того, как владелец сыграет. Типовой контракт модуля:

```ts
// systems/armor.ts — правила брони, никакого Phaser
export function absorb(armor: ArmorState, channel: DamageChannel): boolean {
  if (channel === 'contact') return false;   // контакт всегда в пул ошибок
  if (armor.charged <= 0) return false;
  armor.charged--;
  armor.sinceHitMs = 0;
  return true;
}
```

**Правило 2: игровой шаг не аллоцирует.** Шаг симуляции идёт 120 раз в секунду, поэтому в нём
переиспользуются пул снарядов, пул колец-эффектов, талли подбора, контекст спутников и массив
порядка слотов. Даже выбор цели роя не создаёт копий:

```ts
// systems/targeting.ts — обобщение возвращает ТИП вызывающего, а не «что-то с pos»
export function pickFocusTarget<T extends FocusCandidate>(
  candidates: readonly T[], from: Vec2, rangeSq: number,
): T | null { /* приоритет угрозы > близость; мёртвые не берутся */ }
```

Фиксированный шаг — не формальность: i-frames, дэш и воспроизводимость забега по сиду держатся
именно на нём ([sim/fixedStep.ts](src/sim/fixedStep.ts)), а остаток времени не выбрасывается
(замер: сброс давал ~10% тихого замедления на 24 fps).

## 5. Разбор кода по модулям

### config — числа и данные

- **[tuning.ts](src/config/tuning.ts)** — ВСЕ ощущенческие числа в одном объекте `TUNING`, с
  комментариями, почему число именно такое (каждое защищено замером). Сложность и экономика
  разложены по режимам ЦЕЛИКОМ (`enemyPressure.normal/hardcore`, `chargeSupply.normal/hardcore`):
  режим — это выбор строки, а не набор правок поверх базы.
- **[art.ts](src/config/art.ts) + [textures.ts](src/config/textures.ts)** — имя файла и размер спрайта
  живут в одном месте; адреса — ES-импорты (data: URI в сборке). Масштаб спрайта — **целый делитель
  исходника** (`artDivisor`): при дроби nearest-neighbour мерцает контуром. Правило проверяется
  тестом, который читает размеры самих PNG: таблица обещает, файл — факт.
- **[enemyKinds.ts](src/config/enemyKinds.ts)** — вид врага описан ДАННЫМИ (поведение, множители HP,
  вес спавна, гейт по уровню, свой потолок на поле), а не классом. HP вида — множитель к общей
  кривой `enemyHpForLevel`, поэтому толстый вид не выбивается из неё на высоких уровнях.

### sim и core

- **[fixedStep.ts](src/sim/fixedStep.ts)** — аккумулятор шагов с защитой от «спирали смерти» после
  сворачивания окна.
- **[rng.ts](src/core/rng.ts)** — mulberry32: забег воспроизводим по сиду побайтно.
- **[runRecord.ts](src/core/runRecord.ts)** — запись прогона с **версией правил** (`RUN_RECORD_VERSION = 6`).
  Смена любого контракта (урон, экономика, защита) поднимает версию — прогоны разных игр не
  смешиваются в одной таблице. Тип поля ссылается на константу, чтобы литерал не разошёлся с числом.
- **[runHistory.ts](src/core/runHistory.ts)** — последние 10 результатов и «лучший». Разбор хранилища
  терпимый: мусор отбрасывается, записи чужой версии отсекаются, неизвестная профессия приводится
  к `null`. Недействительные забеги (смена управления по ходу) видны, но рекордом не становятся.
- **[progression.ts](src/core/progression.ts)** — карты, ветки, профессия и кросы. Ключевые правила:
  до профессии — по карте от каждой ветки (выбор стиля, а не лотерея); после — только своя ветка плюс
  крос-карты пар «профессия × вложение ≥ 2»; опыт — **за цену цели**, а не за факт убийства
  (`xpForKill`: танк стоит трёх погонял) — иначе правильное поведение наказывалось медленным ростом.
- **[meta.ts](src/core/meta.ts)** — 5 медалей, каждая открывается фактом ЗАВЕРШЁННОГО забега и даёт
  бонус к старту (не к бою: мета не должна играть за игрока). `metaBonuses` — одна функция на все
  эффекты: добавленное достижение не может «молча ничего не давать».
- **[runStats.ts](src/core/runStats.ts)** — телеметрия: доход разведён по источникам (батареи против
  осколков), расход и залог разведены тоже — по этим двум видно, что мешает поставить фигуру.
- **[store.ts](src/core/store.ts)** — единственное место, где игра трогает localStorage и буфер
  обмена; сбой хранилища не роняет забег. Ключи версионированы (`par.history.v2`, `par.meta.v1`).

### systems — правила игры

- **[charge.ts](src/systems/charge.ts)** — Ток: `amount / cap / held`. Залог (`hold`) делает силу
  фигур постоянной статьёй бюджета; `setCap` подрезает пул по СВОБОДНОМУ остатку; `stepCharge`
  гасит пул выше защищённой доли («Резерв»). Напряжение: `chargeNorm ≥ 0.6` → фигуры на 25% быстрее.
- **[supply.ts](src/systems/supply.ts) + [pickups.ts](src/systems/pickups.ts)** — доход растёт с
  уровнем (иначе расход его перегоняет и все уровни уходят в энергию). Таймер батарей **замирает**,
  когда поле полно: иначе каждое свободное место выдавало батарею немедленно (замер: 17 вместо 9).
- **[pressure.ts](src/systems/pressure.ts)** — давление врагов ступенями по ВРЕМЕНИ забега, а не по
  уровню: уровень растёт от убийств, и привязка к нему давала слабому забегу слабое давление.
- **[spawnDirector.ts](src/systems/spawnDirector.ts)** — кто появится: держим кольцо (погонялы),
  потолок не-погонял (треть живых), потолки видов, взвешенная лотерея, элита с уровня 4. Состав
  считается по живому полю, а не счётчиками — расхождение счётчика и массива и было причиной «трёх
  танков на поле».
- **[targeting.ts](src/systems/targeting.ts)** — общая цель роя: элита → танк → стрелок → ближайший.
  Урон стаи перестал размазываться по толпе («суммонер проседает» оказалось именно этим).
- **[armor.ts](src/systems/armor.ts)** — два канала урона: `contact` всегда в пул ошибок, `ranged`
  тратит один слой брони на залп (держится на окне неуязвимости после срабатывания) и отрастает
  после 8 с без попаданий.
- **[projectiles.ts](src/systems/projectiles.ts)** — один пул на всех стреляющих, пробивание и
  разрывы, враждебные выстрелы — туда же со своим цветом, размером и целью. Пул исчерпан — выстрел
  пропускается, а не роняет цикл.
- **[input.ts](src/systems/input.ts)** — единое `InputState` для клавиатуры и тач-стика; мультитач
  (стик + кнопка дэша), буфер нажатия дэша, выключение ввода на время модальных экранов.
- **[sfx.ts](src/systems/sfx.ts)** — звук синтезом осциллятора: ноты — числа в tuning, файлов нет.
  Порог на частые попадания, чтобы стрельба турелей не превращалась в треск.

### entities — враги и фигуры

- **[enemy.ts](src/entities/enemy.ts)** — машина состояний `seek → windup → charge → recover` с
  тремя самыми важными решениями боя:
  1. **Телеграф — полоса направления**, не кольцо в точке удара (кольцо отдавало ответ сразу, и
     замах перестал требовать чтения). Замах **отменяется**, если игрок ушёл из досягаемости.
  2. **Упреждение прицела**: выпад целится в точку ВСТРЕЧИ (итерации по скорости игрока), иначе
     стоящего игрока нельзя было наказать вообще.
  3. **Перехватчики**: часть погонял встаёт телом на маршрут игрока (точка на дуге виража,
     замораживается, гонка с запасом) — кольцо едет вместе с игроком и само по себе его не встречает.
- **[ally.ts](src/entities/ally.ts)** — одна сущность на четыре роли: устройства (турель, дрон)
  работают всегда, крыло (дух, мот) ходит флангом от взгляда игрока и **гаснет без движения**.
  Постановка платная, залог держится, пока фигура стоит.

### scenes и ui

- **[GameScene.ts](src/scenes/GameScene.ts)** — единственная сцена и единственное «толстое» место:
  связка систем, шаг, HUD (переносится на узком поле), экран смерти с итогом, копируемым отчётом,
  историей, медалями и выбором режима. Единственный путь смерти врага — `damage()`: опыт нельзя
  случайно не начислить. Смерть идемпотентна, мёртвый мир не шагает.
- **[cards.ts](src/ui/cards.ts)** — выбор таланта: тап, клик и клавиши 1–3; мир стоит вместе с
  врагами, у которых на входе в паузу снимается замах («отбой»), а игрок получает передышку.
- **[juice.ts](src/ui/juice.ts)** — слой эффектов (кольца, «+N», следы, тряска) с фиксированными
  пулами; растёт масштабом, а не `setRadius` (21 мкс против 0.08 мкс на кольцо — замерено).
- **[rotateHint.ts](src/ui/rotateHint.ts)** — заглушка вертикального телефона и возврат полного экрана.

### tools

- **[bot/](tools/bot/README.md)** — стенд замеров: та же сцена и тот же шаг, но циклом без рендера.
  Серия из 30 сидов за секунды, воспроизводимость побайтно. История и медали игрока на время прогона
  замораживаются (слепок localStorage на каждый прогон — иначе стенд выдавал бы игроку медали бота).
- **[qa/file-launch-smoke.mjs](tools/qa/file-launch-smoke.mjs)** — смоук упаковки из file:// через CDP
  (без зависимостей): нажимает «1», проверяет движение мира и чистую консоль.
- **[build/packSingleFile.mjs](tools/build/packSingleFile.mjs)** — вшивает JS в HTML и падает с
  понятной ошибкой, если какой-то ассет остался внешним (лучше упасть на сборке, чем дать игроку
  квадраты вместо спрайтов).

## 6. Контракты дизайна (свод чисел)

Все числа — в [tuning.ts](src/config/tuning.ts); здесь — только смысл. Полная история «почему
именно так» — в комментариях к каждому числу и в журнале забегов (§7).

| Контракт | Правило | Почему |
|---|---|---|
| Летальность | 3 удара, 400 мс неуязвимости; контакт всегда в пул | смерть от одного касания давала забеги 6–18 с |
| Дэш | 90 мс, кд 560, ~31 единица пути, i-frames 110 | рывок — спасение в движении, а не транспорт и не «спасение стоя» |
| Экономика | плата за постановку (3–8 Тока) + залог (1–5) | налог за действие фигуры — изобретение; ни Deadlock, ни Diablo, ни PoE 2 его не берут |
| Доход | батарея 7 Ток (+1 каждые 3 уровня), осколок 3; темп растёт с уровнем | фиксированный доход против растущего расхода = голод билда |
| Давление | ступени по времени: 0:00 — 2 врага, 4:00 — 5 + элиты | привязка к уровню размазывала разброс между прогонами |
| Телеграф | полоса направления, 600 мс (хардкор 500), отмена при уходе | читаемая угроза, а не таймер до урона |
| Профессия | 2 карты в ветке; крос — при 2 вложениях во второй | профессия — признание выбора, а не награда за ползабега |

## 8. Замеры, тесты и качество

- **111 тестов** за ~2 с: правила всех чистых модулей — от опыта за танка до терпимого разбора
  хранилища. Тест арта читает размеры реальных PNG.
- **Стенд бота** нашёл дефекты, которые руками не ловились: `setCap` не подрезал пул под залог,
  залог не сбрасывался на старте забега, счётчик отказов врал на порядок, спавн батарей выдавал
  больше обещанного. Каждый — с тестом после правки.
- **Замеры решений**: кольцо слотов по углам (зазоры 120°/180° ровно), упреждение (ближайшая
  дистанция при кайте 59–77 → 7–23), передышка после карты (враг в замахе получает отбой 1200 мс).
- **Смоук упаковки** (`tools/qa`) гоняет собранный `dist/index.html` из file:// в headless Chrome.
- Воспроизводимость: один сид — один прогон побайтно (проверено повторным прогоном стенда).

## 9. Ревью кода

Ревью всего `src/` и `tools/` (октябрь 2026). Что нашлось — и что сделано.

### Найдено и исправлено

1. **Клавиши 1/2 не работали на выборе таланта.** `GameScene` и `CardPicker` брали одни и те же
   коды клавиш через `addKey` (общий объект `Key` на код), и общий `key.off('down')` при
   перерегистрации молча снимал чужие слушатели: панель не закрывалась с клавиатуры, пока 3 работала.
   Поймано смоук-тестом упаковки. Теперь каждый снимает только свой слушатель
   ([cards.ts](src/ui/cards.ts), [GameScene.ts](src/scenes/GameScene.ts)).
2. **Враждебный снаряд рисовался крупнее своего круга попадания** (3 против 2 игровых единиц):
   радиус теперь живёт в снаряде и один для глаз и для физики ([projectiles.ts](src/systems/projectiles.ts)).
3. **Два счётчика убийств** (`killed` в сцене и `kills` в телеметрии) дублировали друг друга —
   оставлен один (`stats.kills`), чтобы HUD и отчёт не могли разойтись.
4. **`runHistory` принимал любую строку как профессию** — мусор из хранилища светился в HUD.
   Неизвестная ветка теперь приводится к `null`, сам забег остаётся.
5. Мелочи: висячий doc-комментарий в [enemy.ts](src/entities/enemy.ts) (осколок переехавшей
   функции), слипшиеся методы в [ally.ts](src/entities/ally.ts).

### Сильные стороны (сохранить при развитии)

- Чистые модули с тестами и «замер вместо мнения» — решения защищены числами прямо в комментариях.
- Единый `TUNING` с режимами-строками: баланс читается и правится одним куском.
- Отсутствие аллокаций в игровом шаге и пулы на всё повторяющееся.
- Терпимый разбор хранилища и версионирование записей: испорченные данные не ломают игру.
- Комментарии объясняют ПОЧЕМУ (с замерами), а не что делает строка.

### Осознанно не тронуто / остаточные риски

- **[GameScene.ts](src/scenes/GameScene.ts) — ~1700 строк.** Это связка сценарного уровня, и делить
  её без живой задачи — риск без выигрыша; если трогать, первым кандидатом будет экран смерти.
- **Модули поверх Phaser не покрыты юнит-тестами** (`projectiles`, `juice`, `input`, `enemy`,
  `ally`) — это плата за слой рендера; всякая логика, которую можно было вынести чистой, вынесена
  и покрыта. Компенсируется смоук-тестом и стендом.
- **Пути к браузеру захардкожены в смоук-тесте** (Chrome/Edge на Windows + `CHROME_PATH` как выход).
- Дизайн-вопросы из журнала (B4, B6, B17) — за ними стоит решение владельца, а не код.
- Бандл Phaser вшит целиком (~1.4 МБ): для одной игры это нормально, код-сплитинг не нужен.
